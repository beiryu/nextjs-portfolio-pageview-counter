## Overview

Duration: 8/2025 - 1/2026

Apptics is an all-in-one platform that turns one-time Shopify shoppers into recurring subscribers — it handles subscription management, payment optimization, and customer retention behind a single dashboard. Selling it needs two very different front ends, and this project is both of them: a long-form marketing site that explains a fairly technical payments product to non-technical eCommerce founders, and a qualification funnel that turns the resulting interest into booked sales calls.

The interesting part of the site is the build pipeline. It is designed in Framer, but instead of shipping Framer's hosted output, the design is pulled into a real codebase with **unframer** — a CLI that compiles Framer components down to plain React. The result is a normal Vite + React + TypeScript app: designers keep working in Framer and re-sync with a single command, while engineering owns the bundle, the routing, the loading strategy, and the deploy.

## Architecture

- **`npm run framer`** — the unframer CLI pulls the Framer project and generates React components into `src/framer/` (hero, features, benefits, onboarding, case studies, calculator, pricing, team, FAQ, nav, footer)
- **`src/components/`** — thin hand-written wrappers around each generated component, applying layout defaults through a shared `withDefaults()` helper, so regenerating the Framer layer never clobbers app-level overrides
- **`src/App.tsx`** — composes the sections and owns everything the design tool can't: lazy boundaries, scroll behaviour, and section anchors for the nav
- **Clean seam between design and code** — the generated directory is disposable and regenerable; all custom logic lives outside it

## Key features

- **Hero + value proposition**: "Turn Your Shoppers into Subscribers" — a single, unambiguous promise above the fold with a primary CTA
- **Feature showcase**: create & manage subscriptions, custom checkouts & upsells, and real-time revenue analytics, each with an animated in-page mockup
- **Benefits grid**: predictable recurring revenue, 2× average order value, live revenue insights, automated billing, fast setup, and failed-payment recovery — driven by a Lottie animation
- **Comparison table**: Apptics vs. competitors across ~20 capabilities (chargeback mitigation, MID management & routing, multi-currency, decline salvage AI, fraud prevention, PCI tokenization, plan A/B testing)

- **Pricing tiers**: 30-day free trial, a one-time-fee Pro plan, and custom Enterprise pricing, with feature breakdowns per tier

## Performance Engineering

This is where owning the code pays for itself — a hosted design-tool export gives you none of it:

- **Route-level code splitting**: every section below the fold is a `React.lazy()` import, so the initial bundle carries only the nav and the hero
- **Custom `LazyLoad` component**: an `IntersectionObserver` with a 300px `rootMargin` mounts each section just before it scrolls into view, with a `Suspense` placeholder holding the layout so nothing shifts
- **Self-hosted fonts**: Plus Jakarta Sans and Fontshare faces vendored into the repo and served from the same origin, removing a third-party round trip on the critical path
- **Static build on Vercel's edge network** — a Vite production build served as immutable, fingerprinted assets

## Design & User Experience

- **Scroll-driven narrative**: sections are ordered as a funnel — problem, product, proof, price — so the page reads as one continuous pitch rather than a set of disconnected blocks
- **Motion as explanation**: dashboard mockups, revenue charts, and checkout flows animate on scroll (Motion One) to show the product working instead of describing it
- **Design tokens**: a small, consistent palette (indigo primary, cyan and lilac accents on near-white surfaces) carried over from Framer's token system
- **Responsive breakpoints**: purpose-built layouts for desktop (1200px and up), tablet (810–1199px), and mobile (under 810px) rather than a single fluid layout that degrades
- **Repeated conversion points**: "Book a Call" and "Calculate My MRR" CTAs recur at every scroll depth so intent is never more than one screen from an action

## Lead Qualification Funnel

Repository: `beiryu/apptics-form-v2` · Live: [apptics-form-iclosed.vercel.app](https://apptics-form-iclosed.vercel.app)

The second surface is a separate Next.js 15 app that replaces the usual "contact us" box. Rather than one intimidating form, it asks ten questions one screen at a time, so each step is a single low-effort decision and the visitor is progressively committed by the time contact details are requested:

- **Intent** — "Want a predictable way to scale your business and MRR?"
- **Pain** — what is holding growth back right now (multi-select)
- **Contact** — name, email, and an international phone field with country detection
- **Business model**, **monthly revenue**, and **monthly ad spend** — the qualification signals that decide whether a prospect is worth a call
- **Payment processing needs** and **what kind of help they want** — routing to the right conversation

Question labels live in one module (`src/lib/questions.ts`) that is the single source of truth for the on-screen copy, the Google Sheet column headers, and the notification email — so a reworded question can never desynchronise the spreadsheet from the form.

## Funnel Engineering

- **Abandonment capture**: a `useAppendOnExit` hook listens for `beforeunload` and flushes whatever has been answered so far via `navigator.sendBeacon`, which survives page unload where `fetch` would be cancelled. A half-finished funnel still produces a usable lead instead of nothing.
- **Exactly-once writes**: that hook guards against duplicates with both per-instance refs and module-level flags, and the final step marks the submission as already appended — so a visitor who completes the funnel and *then* closes the tab is written once, not twice.
- **Booking webhook**: `/api/iclosed-webhook` receives the scheduling callback from iClosed, tolerates its array-wrapped payload shape, pulls the meeting link and invitee email, looks the matching submission back up in Google Sheets by email, and sends the team a Resend email containing the meeting link alongside the prospect's full answers — so whoever takes the call already has the context.
- **Sheets as the datastore**: the Google Sheets API is used deliberately in place of a database. A non-technical sales team reads, sorts, and annotates leads in a tool they already use, with no admin UI to build or maintain.
- **State**: Zustand holds answers across steps, Zod validates each one at its own step rather than in a single submit-time avalanche of errors.
- **Motion**: Framer Motion handles the step transitions; OGL renders an animated WebGL background.
- **Variants**: the funnel ships as several parallel deployments — `v0`, `v1` and `v2` differ in booking provider and positioning, each with a `-meta` counterpart for Meta ad traffic, so copy and flow can be tested against live traffic without branching the product.

This project shows how to get the best of both worlds on a marketing site — the iteration speed of a visual design tool, and the performance, tooling and code quality guarantees of a real front-end codebase, with a regeneration step that keeps the two in sync — and then how to carry that traffic through to a booked call, with a funnel that keeps its data even when the visitor leaves early.
